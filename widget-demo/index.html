ExampleCo

This is a throwaway page standing in for a real company website -- the chat bubble in the bottom-right corner is the actual Chatwoot live chat widget (Option A, see ADR 0009), embedded exactly the way it'd be embedded on a real site: one script tag, nothing custom-built.

Note: this widget talks to the local chatwoot container at http://localhost:3000. This page is served by its own tiny widget-demo container (see docker-compose.yml) at http://localhost:8080 -- it starts automatically with docker compose up -d, nothing extra to run. Found live: opening this file directly as file:// instead of over real HTTP leaves the widget bubble not rendering at all -- a file:// page is a null origin, and the widget's calls beyond the initial script tag don't behave the same way from one.

Try it: click the chat bubble, fill in the pre-chat form (name + email is required), send a message. In the Chatwoot agent dashboard (localhost:3000, "Website Live Chat" inbox), marking that conversation as Resolved fires an automation rule that emails a transcript back to whatever address was given -- see ADR 0009 for why there's no SMTP configured to actually deliver it in this environment, and how that part was verified instead.
